# libGDX 3D notes (load only for 3D games)

libGDX covers light/medium 3D well (casual 3D, low-poly arcade, simulation). For content-heavy 3D
(large worlds, complex animation pipelines, visual editors) write an ADR first - Unity may be the
better tool, at the cost of a new toolchain.

## Building blocks
- `PerspectiveCamera` + `ModelBatch` + `Environment` (ambient + one `DirectionalLight` on mobile).
- Models: glTF 2.0 via the community `gdx-gltf` library (PBR). Verify its current version and
  libGDX compatibility on its GitHub releases before adding it; pin it in `libs.versions.toml`.
  The legacy route is `.g3db` via fbx-conv.
- Physics: `gdx-bullet` (heavy, native) only if needed; simple games use own AABB/sphere tests in
  pure Java (testable).
- Template: start from `templates/libgdx-2d` and replace `PlayScreen`; there is no separate 3D
  template until a 3D game justifies one.

## Mobile budgets (starting points, measure on device)
- < 50k triangles on screen, < 100 draw calls, textures <= 1024 px with mipmaps, compressed (ETC2).
- One directional light, baked lighting/AO in textures where possible, no real-time shadows on low-end.
- Cull: `ModelInstance` frustum checks with bounding boxes; LOD for distant props.

## Pitfalls
- Default shader is per-vertex lit; PBR shaders cost more fill rate - test on a cheap GPU.
- `ModelBatch.render` per instance sorts by default; group by material.
- Dispose `Model`s (not instances) and textures in `dispose()`.

References: https://libgdx.com/wiki/graphics/3d/quick-start , https://github.com/mgsx-dev/gdx-gltf
