# Game music composition (2D and 3D libGDX games)

Entry point for every music task. The workspace already ships a working example: Tidy Tubes
(`games/sortpuzzle`) plays ten original synthesised ambient loops through
`audio/SoundManager.java`, generated by `tools/audio/SfxSynth.java`. This skill generalises
that pattern so any game, 2D or 3D, gets a soundtrack that is original, light, loopable and
policy-safe without hiring a composer first.

| Need | Read | When |
|---|---|---|
| Decide mood, tempo, key, instrumentation per screen | [references/music-brief.md](references/music-brief.md) | Always, before producing anything |
| Generate loops procedurally (no DAW) | [references/procedural-synthesis.md](references/procedural-synthesis.md) | Default path for this workspace |
| Layers, ducking, crossfades, 3D/positional audio | [references/adaptive-and-3d-audio.md](references/adaptive-and-3d-audio.md) | Action games, 3D games, "dynamic music" |
| Licences, encoding, budgets, release checks | [references/licensing-and-export.md](references/licensing-and-export.md) | Before shipping any audio file |

Bundled tools (run from the workspace root):

```powershell
java .claude\skills\game-music-composition\scripts\MusicSynth.java --out <assets\sfx> --name music --style ambient --count 3 --seed 7
java .claude\skills\game-music-composition\scripts\MusicSynth.java --help
.\.claude\skills\game-music-composition\scripts\encode-music.ps1 -Path <assets\sfx>        # every music*.wav -> .ogg + report
```

## Workflow

1. **Brief first.** Fill the one-page brief from `music-brief.md`: one line per game state
   (menu, play, tension, win, lose, shop) with mood, tempo range, key/mode, 2-3 instruments,
   loop length. A game without a brief ends up with one generic loop everywhere; the brief is
   what makes the menu feel like home and the win screen feel earned.
2. **Pick the source.** In order of preference for this workspace:
   - *Procedural* with `MusicSynth.java` (original, zero licence, regenerable, ~100 KB per loop).
   - *Hand-composed* in any DAW/tracker, exported as WAV, then encoded here.
   - *Licensed library* only with a licence that allows commercial apps and no attribution
     the game cannot display. Keep the proof in `play-store/<game>/licences.md`.
   Never use a track because "it sounds like" something; a copyright complaint on Google Play
   is close to unrecoverable for a small publisher.
3. **Produce loops.** Target 20-40 s per loop, seamless (the generator wraps every note around
   the loop end so bar 1 inherits the tail of the last bar). Make 3-10 variants when the player
   can choose, 1-2 when they cannot.
4. **Encode.** `encode-music.ps1` runs FFmpeg (`libvorbis -q:a 3`, mono, 22.05 kHz) and prints
   duration, size and peak level; fix anything it flags before copying files. Generate straight
   into `assets/sfx`, encode with `-RemoveWav`, and never leave WAV sources in `assets/`: the
   SoundManager prefers `.ogg`, so a leftover WAV only ships 25x the bytes for nothing.
5. **Integrate.** Follow the SoundManager contract below. Keep the game logic unaware of audio:
   screens call `sound.startMusic()` / `sound.play(Cue.X)`, nothing else.
6. **Verify on the desktop run first** (`.\gradlew.bat :lwjgl3:run`): loop seam, relative
   level against the effects, settings toggles, then on a device: pause/resume, phone call,
   headphones unplugged, Bluetooth latency.

## Workspace rules (why they exist)

- **Original or licensed only**; synthesised loops are the default because they cost nothing
  and cannot trigger a takedown. Record the source of every file in `assets/sfx/README.txt`.
- **Format**: `.ogg` Vorbis, mono, 22.05 kHz for beds (44.1 kHz only for bright 3D ambiences),
  16-bit source. `Music` streams from disk, so size matters for the APK, not for RAM.
- **Budget**: one loop <= 400 KB, all audio <= 3 MB per game. Google Play's install size is a
  conversion lever; music is usually the first thing that bloats it.
- **Levels**: music WAV normalised to 0.7 peak and played at `MUSIC_VOLUME = 0.32f`; effects
  soft (4 kHz low-pass, -6 dBFS peak, `EFFECTS_GAIN = 0.7f`). The gap keeps cues readable over
  the bed without anyone touching a mixer. The user wants everything gentle: never ship a loop
  that is louder than the current Tidy Tubes beds.
- **Starts on the main menu, never on the splash**; never before the consent form has closed;
  never on first launch before the player has seen a music option (Tidy Tubes opens a picker).
- **Two switches**: `muted` (everything) and `musicOff` (bed only), both persisted in `SaveData`.
- **One `Music` instance alive at a time** (two only during a crossfade); dispose the old one.
  Android has a small hard limit on simultaneous streams and leaks are silent until a crash.
- **Pause with the app**: `pause()` the bed in `Game.pause()`, resume in `resume()` only if it
  was playing. Android pauses audio for calls; resuming blindly plays music over the call UI.
- Nothing audio-related runs on the render thread beyond `play()`/`setVolume()`; decoding is
  streamed by libGDX, so there is nothing to put on a worker thread.

## SoundManager contract (reference: `games/sortpuzzle/.../audio/SoundManager.java`)

```java
public void startMusic()              // loads selected track, loops, volume MUSIC_VOLUME; no-op if off
public void previewMusic(int track)   // settings/picker preview, same instance
public void selectMusicTrack(int t)   // persists, then startMusic()
public void setMuted(boolean)         // all audio; pauses or resumes the bed
public void setMusicOff(boolean)      // bed only
public void pause() / resume()        // from Main.pause()/resume()
public void dispose()                 // Sound + Music instances
```

Files are found by name: `assets/sfx/<cue>.ogg`, else `.wav`, else silent. Music tracks are
`music_01.ogg` ... `music_NN.ogg` with `GameConfig.RELAXING_MUSIC_TRACK_COUNT` matching NN.
A missing file logs an error and stays silent; it never throws, so a half-copied asset folder
cannot crash the game.

libGDX API you will use (verify signatures with `javap` if in doubt):
`Gdx.audio.newMusic(FileHandle)`, `Music.setLooping/setVolume/setPan(pan, volume)/play/pause/
stop/dispose/setOnCompletionListener`, `Sound.play(volume, pitch, pan)` returning a long id,
`Sound.setVolume(id, v)`, `Sound.setPitch(id, p)`, `Sound.setPan(id, pan, volume)`.

## 2D versus 3D games

| | 2D puzzle/casual | 2D action / platformer | 3D |
|---|---|---|---|
| Bed | one ambient loop, player-selectable | one loop per world + tension layer | layered stems (pad / rhythm / lead) by game state |
| Cues | UI, pickup, win, lose | + hit, jump, danger | + footsteps per material, distance-attenuated |
| Spatial | none | pan by screen x | pseudo-3D: volume and pan from camera distance/angle (`adaptive-and-3d-audio.md`) |
| Tempo | 60-80 BPM | 100-140 BPM | 70-120, rises with tension layer |
| Music file count | 3-10 | 2-4 | 2-4 stems x 2-3 states |

libGDX has no true 3D audio API on Android; the reference file shows the pan/volume
attenuation that gets 90 % of the effect at zero cost, and when `setPan` is ignored (some
Android decoders) and you must fall back to volume only.

## Done checklist

- [ ] Brief saved in `games/<game>/docs/audio-brief.md` (or README section), one line per state
- [ ] Every shipped file listed with its origin in `assets/sfx/README.txt`
- [ ] `encode-music.ps1` report: all loops 20-40 s, <= 400 KB, peak between -4 and -1 dBFS
- [ ] Loop seam inaudible on desktop (listen through three repeats)
- [ ] Music starts on the menu, respects `muted` and `musicOff`, survives pause/resume
- [ ] `GameConfig.RELAXING_MUSIC_TRACK_COUNT` (or the game's equivalent) equals the file count
- [ ] `:core:test` green; APK/AAB size delta reported in the task summary
